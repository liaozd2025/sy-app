# ADR-0006：v1 不接推送通道

- **状态**：Accepted
- **日期**：2026-05-24
- **决策者**：产品负责人（grill 访谈 Q9）
- **相关**：[ADR-0007](0007-no-social-v1.md), [PRD §5.11](../../../docs/prd-v1.md#511-总部公告), [PRD §10 风险](../../../docs/prd-v1.md#10-v1-关键风险)

## 背景 (Context)

B 端培训 App 的典型触达通道：

- **App Push (APNs / FCM / 极光)**：开播提醒、必修课发布、公告推送
- **短信**：登录验证码、关键事件兜底通知
- **App 内首页置顶**：仅在用户主动打开 App 时见到

grill 访谈 Q8 / Q9 中产品负责人两次明确：

- "公告推送 = App 推送 + 首页置顶，不发短信"（Q8）
- "开播提醒 v1 不做推送，只在 App 内首页提醒"（Q9）

实际意图收敛为：**v1 完全不接 push 通道**，所有触达都依赖"用户主动打开 App"。

## 决策 (Decision)

**v1 不接入任何推送通道**：

- ❌ 不集成 APNs（iOS）
- ❌ 不集成 FCM（Android）
- ❌ 不接极光 / 个推等第三方推送 SDK
- ❌ 不主动发送通知短信（短信仅用于登录验证码）

所有"需要触达学员"的场景统一降级为：

1. **App 内首页置顶横幅**（公告、必修课、直播预告）
2. **底部 tab 红点提示**（如新公告未读）
3. **个人中心 → 通知中心页**（公告列表）

## 后果 (Consequences)

### 正面
- 开发量大幅压缩：无需申请 APNs 证书、无需注册 FCM 项目、无需对接第三方推送服务
- 无需处理推送权限请求 UX（iOS 推送弹窗会影响新用户首启体验）
- 无短信费用（短信仅登录用，成本可控）
- 无推送内容合规审核压力（推送内容受应用商店和短信服务商双重约束）

### 负面 🔴 **重大留存风险**
- 经销商打开 App 的高频钩子仅"签到 + 每日一题"
- 总部发布必修课、开直播、上福利时，**只有当天打开 App 的学员能看到**
- 长期不活跃用户基本召不回

### 缓解策略
- 运营必须**高频上新**（每周必须有新课/新福利/新公告）
- 总部 SOP：必修课、直播、福利上线前，配套**经销商群微信通知**（线下补推）
- 兑换码模式（详见 ADR-0008）的福利吸引力必须足够"硬"

### v2 升级路径
- v2 引入推送通道时，优先级：开播提醒 > 必修发布 > 福利上新 > 公告
- 推送策略要克制（每日 ≤ 2 条），避免经销商关闭通知权限
- 优先考虑微信服务号模板消息（B 端学员多在微信生态内）
