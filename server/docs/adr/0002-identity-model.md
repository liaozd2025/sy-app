# ADR-0002：身份模型 = 白名单单层 + 公司归属

- **状态**：Accepted
- **日期**：2026-05-24
- **决策者**：产品负责人（grill 访谈 Q2）
- **相关**：[ADR-0001](0001-business-positioning.md), [PRD §3](../../../docs/prd-v1.md#3-用户与角色), [PRD §5.1](../../../docs/prd-v1.md#51-身份与登录)

## 背景 (Context)

确认 B 端培训定位后，需要决定经销商**怎么进 App、彼此什么关系**。现有 `dh_live_member` 表只有 `memberId / phone / nickname / avatar / status`，无任何经销商层级、公司、上下级字段。

四种候选模式：

- **A. 白名单单层**：运营导入手机号，短信登录，所有人平等
- **B. 邀请码多层**：总部发码给一级、一级再发给下属
- **C. 公司主子账号**：一公司一主账号 + N 子账号
- **D. 开放申请 + 审核**

同时需决定：一级经销商公司里"老板 + 销售们"如何区分。

## 决策 (Decision)

**A + 公司归属**：

1. **白名单单层**：总部运营在 admin-web 导入学员手机号；学员用手机号 + 短信验证码登录；所有学员 App 内权限平等，无上下级
2. **公司归属**：每个学员关联一家"经销商公司 (organization)"，但 App 内身份不区分"老板/销售"
3. 公司维度可在 admin-web 看汇总报表（这家公司学了多少、平均完成率等）

讲师 (`dh_live_creator`) 仅作为**内容署名**实体，**不绑账号、不登录、不发权限**。

## 后果 (Consequences)

### Schema 影响
- **新增** `dh_live_organization` 表（公司主体）
- **修改** `dh_live_member` 加 `organization_id` 字段（nullable）

### 后台工具影响
- admin-web 需要"经销商公司管理"模块（CRUD）
- admin-web 学员管理需支持"批量导入手机号（绑定到公司）"

### 正面
- 极简登录链路（无注册、无审核、无邀请码）
- 公司维度报表能力天然可建
- DB 改动最小

### 负面
- 老板无法"自己拉销售进 App"，必须通过总部白名单导入 → 总部运营负担加重
- 不区分公司内层级 → 老板看不到自己销售的明细（要等 v2 经销商个人后台）

### v2 升级路径
- 如需"老板能管下属"，可基于 organization_id 引入 `member_role` 字段（owner / staff）
- 如需多层级分销，可在 organization 表加 `parent_org_id` 字段
