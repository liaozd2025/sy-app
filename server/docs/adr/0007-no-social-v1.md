# ADR-0007：v1 无社交（无榜单 / 无社区 / 无分享）

- **状态**：Accepted
- **日期**：2026-05-24
- **决策者**：产品负责人（grill 访谈 Q7、Q8）
- **相关**：[ADR-0006](0006-no-push-notifications-v1.md), [PRD §6](../../../docs/prd-v1.md#6-v1-明确推迟项防止-vibe-coding-跑偏)

## 背景 (Context)

现有原型与 DB 设计支持丰富的社交互动能力：

- `dh_live_feed`（社区动态流）
- `dh_live_comment`（评论）
- `dh_live_member_favorite` / `dh_live_member_like` / `dh_live_creator_follow`（收藏 / 点赞 / 关注）
- 原型有"发布社区帖子"页面

但 grill 访谈系列决策中产品负责人**一致选择最克制的方案**：

- Q7 排行榜：选"v1 不做榜，只看个人晶升徽章"
- Q8 社区 feed：选"v1 砍掉，DB 表保留，v2 启用"
- Q8 分享给客户：选"不做。只实现 App 内内容消费，转发推 v2"

## 决策 (Decision)

**v1 完全无社交属性**：

### 砍掉的功能
| 功能 | 状态 |
|------|------|
| 积分排行榜（月度 / 累计 / 公司） | ❌ 全不做 |
| 社区 Feed（发现页内容动态流） | ❌ 砍 |
| 评论 / 回复 | ❌ 砍 |
| 收藏 / 点赞 / 关注讲师 | ❌ 砍 |
| 健康内容分享到微信 / 朋友圈 | ❌ 砍 |
| 分享给客户的带水印 H5 | ❌ v2 |
| 邀请好友 | ❌ 不做（白名单制） |

### DB 处理
- 上述功能对应的表 **保留不删**，仅 UI 隐藏入口：
  - `dh_live_feed`, `dh_live_comment`, `dh_live_member_favorite`, `dh_live_member_like`, `dh_live_creator_follow`
- v2 启用时无需新建表，仅恢复 UI

### 学员驱动力来源
v1 学员的全部驱动力来自**纵向**而非横向：

- 个人晶升等级徽章（青铜 → 钻石）
- 个人积分账户成长
- 个人连签天数
- 兑换福利的真实物品/权益

## 后果 (Consequences)

### 正面
- 极度收敛、内向闭环的产品形态
- 无社区运营压力（不需要审核帖子、不需要拉新发帖人、不需要冷启动）
- 无"看着别人学得多就不爽"的社交焦虑
- 开发量大幅压缩（评论引擎、点赞计数、Feed 算法、分享生成器全部不做）

### 负面 🔴
- **失去横向比较的驱动力**：没有"看到隔壁公司学了 50 门课，我也得追"的社交压力
- **失去 B 端杀手锏**：经销商无法把内容分发给终端用户，"知识弹药库"的对外价值无法兑现
- **失去口碑传播**：没有分享 → 没有有机增长 → v1 完全依赖运营白名单导入

### 缓解策略
- v1 个人中心的"晶升徽章"展示要做得**有面子**（动画、特效、入场仪式感）
- 福利商城兑换记录在个人页强化展示（"我已经兑换过 X 件福利"）
- **运营在线下微信群激活社交比较**：定期发"本月学习之星"红榜

### v2 启用次序建议
1. 分享给客户（最大业务价值）
2. 排行榜（公司维度榜，激活公司内 PK）
3. 收藏 / 关注（轻量个人功能）
4. 评论 / 社区 Feed（运营复杂度最高，最后做）
