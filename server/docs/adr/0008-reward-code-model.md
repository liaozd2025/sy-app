# ADR-0008：积分商城 = 兑换码模式

- **状态**：Accepted
- **日期**：2026-05-24
- **决策者**：产品负责人（grill 访谈 Q7）
- **相关**：[PRD §5.8](../../../docs/prd-v1.md#58-积分商城兑换码模式)

## 背景 (Context)

学员的积分需要消耗出口，否则激励系统无落地。候选模式：

| 模式 | 描述 | 复杂度 |
|------|------|--------|
| A. 实物商城（带库存物流） | 真实电商：SKU、库存、地址、物流 | 高（需对接 ERP / 物流） |
| B. 兑换码模式 | 总部发"兑换码"，学员扣积分领码，线下发货 | 低 |
| C. 虚拟权益 | 解锁高级课程、头像框、纪念徽章 | 低（但 B 端"插汗"不足） |
| D. 不消耗 | 积分纯为晶升和排行 | 极低（但无获得感） |

## 决策 (Decision)

**v1 = 兑换码模式（B）**：

1. 总部运营在 admin-web 创建福利 SKU（`dh_live_reward_item`）：名称、图片、所需积分、库存、说明
2. 运营预先生成或上传一批兑换码（`dh_live_reward_code`），每个码对应一个福利
3. 学员在 App 商城兑换 → 扣积分 → 系统从该福利码池中取出一个未使用码 → 显示给学员
4. **实物发货由总部线下完成**（学员凭兑换码私信运营 / 微信群登记）
5. App 内仅记录"已兑换 + 兑换码"，**不参与物流追踪**

### Schema 变更（新增 3 张表）
- `dh_live_reward_item`：福利 SKU 主表
- `dh_live_reward_code`：兑换码池
- `dh_live_member_reward_record`：学员兑换记录

### 关键不变式
- 兑换码**一码一用**：取出时立刻标记 `is_used = true` + `used_by + used_time`
- 库存 = `dh_live_reward_code` 中 `is_used = false` 的数量
- 学员积分扣减与兑换码取出必须在**同一事务**内完成，避免扣分但拿不到码

## 后果 (Consequences)

### 正面
- **不对接 ERP**：v1 不需要打通颐享公司原有进销存系统
- **不对接物流**：避免快递鸟、菜鸟、顺丰等接口对接
- **不做退换货**：兑换不可逆
- 开发量极小：3 张表 + 一个事务方法

### 负面
- 兑换体验偏弱：学员拿到的是"码"而不是"商品"，要二次找运营登记发货
- 福利吸引力 100% 依赖**真实物品价值**：码本身无情感价值
- **运营负担**：兑换码池要预先生成、线下发货要人工跟踪、登记表要 Excel 维护

### 验证约束
- 上线前总部需储备 ≥ 5 个福利 SKU + 每个 SKU 至少 50 个兑换码
- 福利必须真的"硬"：实物礼品、年会名额、新品试用、咖啡券等
- 运营 SOP：兑换记录要导出 Excel 与发货物流人员对账

### v1.5 / v2 升级路径
- **v1.5**：兑换记录支持导出 Excel；学员侧增"我已收到货"反馈按钮
- **v2**：考虑接入第三方礼品卡平台（兑吧、积分宝），实现自动发货
- **v3**：如业务规模扩大，再评估是否对接 ERP 做真实物商城
